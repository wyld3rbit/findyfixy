# Day 8. Cost and context control

**Outcome:** a measured before/after on cost per run, with budgets enforced at a gateway and quality held above the Day 5 gate.

## Concept (25 min)

**Where the cost and the time go.** Inference has two phases. Prefill processes every input token in parallel and builds the key-value (KV) cache, the model's working memory for the prompt. Its cost scales with input length, and it sets time to first token. Decode then generates output one token at a time, each step reading the whole KV cache. It is sequential, so it dominates wall-clock latency for long answers. Hosted providers price the two phases separately, with output tokens costing several times more than input tokens.

**Cost is a design property.** It is set by routing, context size, caching and output length, all decided in the architecture. Tuning after launch trims the edges.

**Five levers, in order of typical impact.**

1. **Routing.** The share of runs that reach the large model (Day 1). Halving escalation often beats every other lever combined.
2. **Context budget.** Every retrieved chunk and every tool schema is paid in prefill on every call. Fewer, better chunks (Day 4) and only the tools a node needs (Day 2).
3. **Prefix caching.** If consecutive requests share an identical prefix, the runtime reuses the stored KV cache instead of recomputing it. That cuts prefill time and, on hosted APIs, input price. It only works when the stable parts (system prompt, schema, tool definitions) come first and the variable parts come last. One changed byte early in the prompt invalidates everything after it.
4. **Response caching.** Identical requests are answered from a cache. Semantic caching matches near-identical ones by embedding similarity; it saves more and risks returning a stale or wrong answer, so it needs a tight threshold and an expiry.
5. **Output length.** Cap `max_tokens` at what the schema needs. Decode is the slow phase.

**The gateway is a control plane.** A proxy such as LiteLLM sits between every caller and every model. It holds the provider keys, so applications never do. It enforces budgets and rate limits per key or team, logs spend centrally, routes by model alias and fails over between providers. Model choice becomes configuration instead of code, and finance gets one ledger.

**Pricing local models.** A local token has no invoice, but it is not free: hardware, power and the throughput you give up. Assign each alias a reference price per million tokens, set at what a hosted model of that class charges. Cost per run is then comparable across local and hosted, and the build-versus-buy decision becomes arithmetic.

## Lab (90 min)

### 1. Baseline

From Langfuse, record average tokens in, tokens out, latency, escalation rate and reference cost across the golden set. Write them in `notes/day8.md`.

### 2. LiteLLM proxy

Versions 1.82.7 and 1.82.8 were compromised on PyPI in March 2026. Exclude them and commit the lockfile.

```bash
uv add "litellm[proxy]!=1.82.7,!=1.82.8"
git add uv.lock && git commit -m "lock litellm"
```

`litellm.yaml` with two aliases: `triage-small` pointing at Ollama `qwen2.5:1.5b`, and `triage-large` pointing at Ollama `qwen2.5:7b`. Set each alias's reference price. Virtual keys need a database: point LiteLLM at the Day 3 Postgres. Create a virtual key with a `max_budget`. Point both graph nodes at the proxy through its OpenAI-compatible endpoint. Push runs past the budget and confirm the key is refused.

### 3. Pull the levers

One change at a time. Re-run the golden set after each and record reference cost, latency and faithfulness:

1. Cap retrieved context at 3 chunks of 400 tokens.
2. Order the prompt for prefix caching: system prompt and schema first, variable content last.
3. Tune the escalation threshold: 0.6, 0.7, 0.8.
4. Set `max_tokens` to 300.

### 4. Optional: hosted model swap

If you have an API key for a hosted model (Claude or another), add it as a third alias, `triage-frontier`, and route escalations there for one golden-set run. Compare cost, latency and faithfulness against `triage-large`. This is the evidence behind the build-vs-buy call. The course works without it.
