# Day 9. Deploy and operate

**Outcome:** the agent runs as a containerised service with human-on-the-loop approval for destructive actions and a scheduled eval that catches regression and drift.

## Concept (25 min)

- **Human-in-the-loop vs human-on-the-loop.** In the loop: a person approves every step. On the loop: the system acts inside policy, and a person approves only the destructive tier and watches the rest. The second scales.
- **LangGraph interrupts.** A graph can pause before a node, persist its state with a checkpointer, and resume after approval. That is the approval gate.
- **Drift has three sources.** The model changes (provider update), the data changes (new services, new failure modes), the prompts change (your team). A scheduled eval on a fixed golden set catches all three. A rising escalation rate is an early signal.
- **Promotion path.** Change, eval gate in CI, shadow run against live traffic, canary, full rollout. Rollback is a config flip.

## Lab (90 min)

### 1. Service

`app/api.py` with FastAPI:

- `POST /triage` starts a run and returns `{run_id, status, triage}`.
- When the policy allows `rollback`, the graph pauses (`interrupt_before=["execute"]`, Postgres checkpointer), and the status is `awaiting_approval`.
- `POST /runs/{id}/approve` resumes the run. `POST /runs/{id}/reject` closes it.

```bash
uv add langgraph-checkpoint-postgres
```

### 2. Container

Ask Claude Code for a `Dockerfile` (multi-stage, non-root user) and add the `api` service to `docker-compose.yml` next to `db`. Ollama stays on the host. Containers reach it at `host.docker.internal` (on older Colima, `host.lima.internal`); test with `curl` from inside the container and put the working address in `OLLAMA_BASE_URL`. Pin every image tag.

### 3. Scheduled eval

`scripts/nightly_eval.sh` runs the eval, compares it to the last report, and writes `reports/drift-<date>.md` flagging any metric down more than 0.05, or an escalation-rate rise above 10 points. Schedule it with `cron` or `launchd`.

### 4. Shadow mode

Add a `SHADOW_PROMPT` env var. When it is set, each request also runs the candidate prompt, logs both results to Langfuse with a `variant` tag, and returns only the current one.

### 5. Demo screen

```bash
uv add streamlit
```

`ui/app.py`, a Streamlit page that calls the API:

- A text box for an incident and a Triage button.
- A result card: severity, component, next action, confidence, model used.
- The 3 prior incidents memory recalled.
- When the status is `awaiting_approval`: Approve and Reject buttons.
- A link to the run's Langfuse trace.

Add a `ui` service to `docker-compose.yml`. This is the screen you show on Day 10.

## Self-check

- [ ] `docker compose up` brings up db, api and ui; the screen returns a triage.
- [ ] A rollback request pauses, and Approve on the screen resumes it.
- [ ] One nightly report exists.
- [ ] Shadow runs appear in Langfuse tagged by variant.

## Drill

"How do you take an agent from prototype to production without betting the company?"

Answer shape: the promotion path. Eval gate, shadow, canary, rollout, one-flip rollback. Humans on the loop for destructive actions. A scheduled eval for drift. Name what each stage catches.
