# Day 1. Setup and first graph

**Outcome:** a LangGraph agent that answers with a small local model first and escalates to a larger local model only when the small answer is weak.

## Concept (20 min)

- **Why small-model-first.** Most triage questions are routine. A 1.5B model answers them fast and cheap. A larger model is reserved for the hard tail. The routing policy is the cost lever.
- **Why a graph.** An agent is a state machine: nodes do work, edges decide what runs next, state carries context. LangGraph makes that explicit, so every step can be traced, tested, retried and paused for a human.
- **Escalation signal.** Options, cheapest first: the model's own confidence field in a structured answer; a rule (missing fields, low retrieval score); a judge model. Start with the first.
- **All open source.** Both models are Qwen2.5 (Apache 2.0) on Ollama (MIT). A hosted frontier model is an optional swap on Day 8, not a dependency.

### 4. The router graph

Ask Claude Code to build `app/graph.py` with this spec:

- State: `question`, `answer`, `confidence` (0 to 1), `model_used`.
- Node `small`: `ChatOllama(model="qwen2.5:1.5b")` with structured output `{answer: str, confidence: float}`.
- Conditional edge: if `confidence >= 0.7` go to END, else go to `large`.
- Node `large`: `ChatOllama(model="qwen2.5:7b")`, same schema.
- Model names come from `.env` (`SMALL_MODEL`, `LARGE_MODEL`) so they can be swapped later.
- `main()` runs 5 sample questions and prints the model used and latency for each.

Skeleton for reference:

```python
from typing import TypedDict
from langgraph.graph import StateGraph, END

class S(TypedDict, total=False):
    question: str; answer: str; confidence: float; model_used: str

g = StateGraph(S)
g.add_node("small", small_node)
g.add_node("large", large_node)
g.set_entry_point("small")
g.add_conditional_edges("small", lambda s: END if s["confidence"] >= 0.7 else "large")
g.add_edge("large", END)
app = g.compile()
```
