# Day 6. Observability

**Outcome:** every run traced in Langfuse with tokens, cost, latency and model per step; eval scores attached to traces; three questions you can answer from the dashboard.

## Concept (25 min)

**Logs, metrics, traces.** Logs are events. Metrics are aggregates over time. A trace is the causal tree of one request: a root span for the run, child spans for each graph node, and grandchildren for each model call, tool call and retrieval. Each span carries start, duration, status and attributes. For an agent, the trace is the unit of debugging. A wrong answer is explained by what was retrieved, which model answered, what the prompt contained and which branch the graph took. Only the trace holds all four.

**What to record on an LLM span.** Model and version, input and output tokens, latency, time to first token, the prompt template version, and the routing decision. Cost is derived: tokens times a price table. Keep the price table in config, because prices change.

**OpenTelemetry GenAI semantic conventions** standardise these attributes: `gen_ai.request.model`, `gen_ai.usage.input_tokens`, `gen_ai.usage.output_tokens` and others. Emitting standard attributes keeps traces portable between backends. Langfuse accepts OpenTelemetry, so the instrumentation outlives the vendor choice.

**Scores on traces.** Attach eval scores, judge results and user feedback to the trace ID. Quality then sits next to cost and latency on the same record. A faithfulness drop becomes a filter that returns the exact runs and the exact retrievals behind it.

**What leaders read.** Cost per resolved incident, not cost per call. Escalation rate. p95 latency by node, because averages hide the tail users feel. Error and retry rates. Quality score trend. Each one is an aggregate over traces, so the traces come first.

**What changes at scale.**

- **Volume.** You sample. Keep every error and every low-scoring run, and a percentage of the rest.
- **Privacy.** Prompts and outputs contain user data. Redact at the source, set retention, restrict access.
- **Cardinality.** Do not put unbounded values such as user IDs into metric labels; they belong on spans.
- **Overhead.** Export asynchronously, so a slow tracing backend never slows a request.

## Lab (90 min)

### 1. Run Langfuse locally

Langfuse runs Postgres, ClickHouse, Redis and MinIO as containers. On a 16 GB Mac, give the container runtime 8 GB for this (Colima: `colima stop && colima start --memory 8`; Docker app: Settings, Resources), close other heavy apps, and stop Langfuse when not in use.

Ask Claude Code to put Langfuse's official compose file in `code/infra/langfuse/`, taken from the latest release tag of the Langfuse repo, with image tags pinned and its own secrets in `code/infra/langfuse/.env`. Then:

```bash
docker compose -f infra/langfuse/docker-compose.yml up -d
# open http://localhost:3000, create a project, copy the keys into code/.env
```

It lives inside the repo but runs as its own stack. Stop it with `docker compose -f infra/langfuse/docker-compose.yml down`.

Add these to `.env`: `LANGFUSE_PUBLIC_KEY`, `LANGFUSE_SECRET_KEY`, `LANGFUSE_HOST=http://localhost:3000`.

### 2. Instrument

```bash
uv add langfuse
```

Pass the Langfuse LangChain `CallbackHandler` in the graph's `config={"callbacks": [handler]}`. Wrap retrieval and ingestion in `@observe()` so they show as spans. Tag each trace with `model_used` and `escalated`.

### 3. Attach eval scores

Change `eval_answers.py` so each golden case writes its RAGAS scores to its trace with the Langfuse score API.

### 4. Answer from the dashboard

Run the golden set twice. Then answer in `notes/day6.md`:

1. Average cost per run, local only vs escalated.
2. The slowest node at p95.
3. The 3 lowest-faithfulness traces, and what retrieval returned for each.
