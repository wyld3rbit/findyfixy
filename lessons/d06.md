# Day 6. Observability

**Outcome:** tracing is a harness component built on the OpenTelemetry SDK, with Langfuse v4 as the backend; every FindyFixy run and every eval case is a trace with tokens, latency and model per step, eval scores sit on their traces, and the eval run is faster without changing a score.

## Concept (25 min)

**Logs, metrics, traces.** Logs are events. Metrics are aggregates over time. A trace is the causal tree of one request: a root span for the run, child spans for each graph node, and grandchildren for each model call, tool call and retrieval. Each span carries start, duration, status and attributes. For an agent, the trace is the unit of debugging. A wrong answer is explained by what was retrieved, which model answered, what the prompt contained and which branch the graph took. Only the trace holds all four.

**What to record on an LLM span.** Model and version, input and output tokens, latency, time to first token, the prompt template version, and the routing decision. Cost is derived: tokens times a price table. Keep the price table in config, because prices change.

**OpenTelemetry GenAI semantic conventions** standardise these attributes: `gen_ai.request.model`, `gen_ai.usage.input_tokens`, `gen_ai.usage.output_tokens` and others. Emitting standard attributes keeps traces portable between backends. Langfuse ingests OpenTelemetry over HTTP at `/api/public/otel` and renders spans with `gen_ai.*` attributes as model generations, so the instrumentation outlives the vendor choice. The GenAI conventions are still evolving: attribute names can shift between releases.

**Scores on traces.** Attach eval scores, judge results and user feedback to the trace ID. Quality then sits next to cost and latency on the same record. A faithfulness drop becomes a filter that returns the exact runs and the exact retrievals behind it.

**What leaders read.** Cost per resolved incident, not cost per call. Escalation rate. p95 latency by node, because averages hide the tail users feel. Error and retry rates. Quality score trend. Each one is an aggregate over traces, so the traces come first.

**What changes at scale.**

- **Volume.** You sample. Keep every error and every low-scoring run, and a percentage of the rest.
- **Privacy.** Prompts and outputs contain user data. Redact at the source, set retention, restrict access.
- **Cardinality.** Do not put unbounded values such as user IDs into metric labels; they belong on spans.
- **Overhead.** Export asynchronously, so a slow tracing backend never slows a request.

## Build

Blueprint first: the OpenTelemetry SDK (Apache-2.0) and the GenAI semantic conventions for instrumentation, Langfuse v4 (MIT core, `ee/` excluded; check `LICENSE` at the pinned tag) as the backend. No Langfuse SDK and no LangChain callback: only score attachment is Langfuse-specific. Langfuse removes its legacy APIs on 2026-11-16, so only v4 is used.

### 0. Test isolation fix

`tests/test_scan_private.py` builds throwaway git repos but inherits `GIT_INDEX_FILE` when a hook runs under `git commit -a`, so 8 tests read the real index and fail. The fixture clears every `GIT_*` variable for its subprocesses. Prove it: the tests pass when run with `GIT_INDEX_FILE` set to a foreign path.

### 1. Answer first, judge after, with per-phase timing

The harness runner answers every case, then judges every case, so each model loads once instead of swapping every case. Reports gain per-phase timing (answer, judge, wall). Proof that no score moves: the next full run is identical, case by case, to the attested run of 2026-11-10; only timing changes. `make eval-compare` does the case-by-case check, so every later step that must not move a score can prove it the same way.

### 2. Langfuse v4 stack

`code/infra/langfuse/`: the official compose file from a pinned v4 release tag (at least v4.59.0), every image pinned by digest and scanned with Grype before first use, its own secrets in `code/infra/langfuse/.env` (git-ignored, written by `make obs-secrets`), bound to 127.0.0.1. Started with `make obs-up`, stopped with `make obs-down`. Colima at 8 GB for this day. Stop it when not in use.

### 3. Tracing as a harness component

`code/harness/trace/`: an OpenTelemetry tracer with a batch exporter over OTLP HTTP, so a slow or dead backend never blocks a run. Spans: the run (root), each graph node, each model call (`gen_ai.request.model`, `gen_ai.usage.input_tokens`, `gen_ai.usage.output_tokens`, latency), recall, the tool call, and each judge call. The app's existing events map onto spans through an adapter; the harness still never imports the app. Configuration (endpoint, keys) is read at the edge. With no endpoint set, tracing is off and nothing else changes.

### 4. Eval scores on traces

Each golden case runs under its own trace. Its scores (severity match and the 4 judged measures) attach to that trace through Langfuse's score API, behind a small backend seam so another backend can replace it.

### 5. Visualizer and artifacts

The Tracing box turns built, with its code reference; the event log links each run to its trace. READMEs, CHANGELOG, tracker, ADR snapshot.

### 6. Answer from the dashboard

Run the golden set twice. Answer in the Results section:

1. Cost per run, local only against escalated, from a price table in config (local models cost nothing; a reference price per token makes the comparison).
2. The slowest node at p95.
3. The 3 lowest-faithfulness traces, and what recall returned for each.

### Packages

`opentelemetry-api`, `opentelemetry-sdk`, `opentelemetry-exporter-otlp-proto-http`: Apache-2.0, maintained by the OpenTelemetry project, among the most downloaded packages on PyPI. The release cooldown (`exclude-newer`) moves forward to about 7 days before the day, then `make audit`.
