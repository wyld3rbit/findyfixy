# Day 9. Deploy and operate

**Outcome:** the agent runs as a containerised service with human-on-the-loop approval for destructive actions and a scheduled eval that catches regression and drift.

## Concept (25 min)

**Human-in-the-loop versus human-on-the-loop.** In the loop, a person approves every step. It is safe and it does not scale: the human becomes the throughput limit and starts rubber-stamping. On the loop, the system acts autonomously inside a policy, a person approves only the destructive tier, and everything else is observable after the fact. The design question is where to draw the tier boundary, and the answer is reversibility and blast radius. Reading logs is free to undo. A rollback in production is not.

**Durable execution.** An approval can take minutes or hours. The process that started the run may restart in between. So the run's state cannot live in memory. LangGraph's checkpointer writes state to Postgres after every step. An interrupt before a node stops the run and persists it. Resuming loads the checkpoint and continues from exactly that point, in any process.

Resume implies replay. Any step that runs again must be safe to run again, so external actions need idempotency keys. Approving twice must not roll back twice.

**Drift has three sources, and they look alike from outside.**

- **The model changes.** A provider updates weights behind the same name, or you upgrade a local model.
- **The data changes.** New services, new failure modes, a stale memory index.
- **The prompts and code change.** Your own team.

A scheduled eval on a fixed golden set catches all three, because it holds the questions constant while everything else moves. Operational signals catch drift earlier: escalation rate, validation-failure rate and judge scores on sampled live traffic.

**The promotion path.** Each stage catches a different failure.

- **Eval gate in CI** catches regressions on known cases.
- **Shadow** runs the candidate on live traffic and discards its output. It catches failures on real inputs at zero user impact, and it doubles inference cost while it runs.
- **Canary** serves the candidate to a small slice of real users. It catches what only real impact reveals.
- **Rollout**, with rollback as a configuration flip, not a deploy.

**Containers and the model host.** The application ships as a container: multi-stage build, non-root user, pinned base image. The model server stays where the accelerator is. Docker on a Mac cannot reach the Apple GPU, so Ollama runs on the host and containers call it over the network. Production uses the same split: application pods scale on CPU, and model serving runs on its own GPU hosts.

## Lab (90 min)

### 1. Service

`app/api.py` with FastAPI:

- `POST /triage` starts a run and returns `{run_id, status, triage}`.
- When the policy allows `rollback`, the graph pauses (`interrupt_before=["execute"]`, Postgres checkpointer), and the status is `awaiting_approval`.
- `POST /runs/{id}/approve` resumes the run. `POST /runs/{id}/reject` closes it.

```bash
uv add langgraph-checkpoint-postgres
```

### 2. Container

Ask Claude Code for a `Dockerfile` (multi-stage, non-root user) and add the `api` service to `docker-compose.yml` next to `db`. Ollama stays on the host. Containers reach it at `host.docker.internal` (on older Colima, `host.lima.internal`); test with `curl` from inside the container and put the working address in `OLLAMA_BASE_URL`. Pin every image tag.

### 3. Scheduled eval

`scripts/nightly_eval.sh` runs the eval, compares it to the last report, and writes `reports/drift-<date>.md` flagging any metric down more than 0.05, or an escalation-rate rise above 10 points. Schedule it with `cron` or `launchd`.

### 4. Shadow mode

Add a `SHADOW_PROMPT` env var. When it is set, each request also runs the candidate prompt, logs both results to Langfuse with a `variant` tag, and returns only the current one.

### 5. Demo screen

```bash
uv add streamlit
```

`ui/app.py`, a Streamlit page that calls the API:

- A text box for an incident and a Triage button.
- A result card: severity, component, next action, confidence, model used.
- The 3 prior incidents memory recalled.
- When the status is `awaiting_approval`: Approve and Reject buttons.
- A link to the run's Langfuse trace.

Add a `ui` service to `docker-compose.yml`. This is the screen you show on Day 10.

## Drill

"How do you take an agent from prototype to production without betting the company?"

Answer shape: the promotion path. Eval gate, shadow, canary, rollout, one-flip rollback. Humans on the loop for destructive actions. A scheduled eval for drift. Name what each stage catches.
