# Day 4. Memory II: hybrid retrieval

**Outcome:** a retriever that fuses keyword and vector search, reranks with a cross-encoder, and beats vector-only on recall@5 by a number you measured.

## Concept (25 min)

- **Vector search misses exact tokens.** Error codes, hostnames and ticket IDs. BM25 catches them. Vector search catches paraphrase. Production retrievers use both.
- **Reciprocal-rank fusion (RRF).** Merge ranked lists without calibrating scores: `score = sum(1 / (k + rank))`, with k = 60. Simple and robust.
- **Cross-encoder rerank.** Retrieve 30 to 50 cheaply, then rescore the pairs with a model that reads query and chunk together. `BAAI/bge-reranker-base` runs locally. Rerank the top candidates only; it is the expensive step.
- **Measure retrieval separately from generation.** If retrieval is wrong, no prompt fixes it. Metrics: recall@k (did the right chunk appear) and MRR (how high).

### 1. Labelled queries

### 2. Three retrievers

In `app/retrieve.py`:

1. `vector(q, k)`: pgvector cosine.
2. `hybrid(q, k)`: BM25 top 50 plus vector top 50, fused with RRF.
3. `hybrid_rerank(q, k)`: hybrid top 30, reranked with `CrossEncoder("BAAI/bge-reranker-base")`.

Add an optional `service` metadata filter to all three.

### 3. Measure

`app/eval_retrieval.py` prints recall@5, MRR and p50 latency per retriever. Save to `notes/day4.md`.

### 4. Wire it in
